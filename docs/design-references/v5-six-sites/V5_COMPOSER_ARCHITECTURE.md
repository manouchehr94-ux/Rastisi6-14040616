# V5 Visual Layout Composer — معماری، ماتریس وضعیت و محدودیت‌ها

R4 تنها منبع حقیقت است (داده، رندر، Mutation، Draft/Preview/Publish/Undo-Redo). مرجع HTML فقط الگوی UX بود؛ هیچ موتور یا رندر موازی ساخته نشده است.

## مدل داده

```
Page → Container (ردیف) → Cell (۱۲ واحد نسبی) → Blocks (Section ها)  XOR  یک Container تو در تو (Group)
```

* `StorefrontContainer.parent_cell` (افزودنی، migration `0022`) — Cell یا Block دارد یا یک Group؛ هرگز هر دو.
* Manager پیش‌فرض فقط ردیف‌های سطح صفحه را برمی‌گرداند؛ `all_objects` کل درخت را. کد قدیمی بدون تغییر همان را می‌بیند.
* Group = همان Container؛ ظاهر در `Container.settings` (کلیدهای پراکنده): `title`, `description`, `title_visible`, `style{...}`، حالت‌های پس‌زمینهٔ `gradient`/`image`، `axis="vertical"`.
* `span` در هر سطح نسبت‌های صحیح مجموع ۱۲ (کف ۲) است؛ پس تغییر اندازهٔ والد، نسبت فرزندان را نگه می‌دارد (فرزندان نسبت به خانهٔ خودشان‌اند).
* سقف‌ها: ۶ خانه در هر Group، عمق ۸، ۲۴۰ خانه در صفحه.

## Mutation ها (هرکدام = یک Revision = یک Undo)

`row.add` · `cell.split(axis, count)` · `container.set_layout(axis, count)` · `container.add_cell` · `cell.remove` · `container.remove_group` · `cell.duplicate` · `container.duplicate` · `cell.move` · `container.move` · `container.resize(spans)` · `container.update_settings` (عنوان/توضیح/style/پس‌زمینه/موبایل).
محتوا هنگام تقسیم، کپی، جابه‌جایی و تغییر چیدمان از دست نمی‌رود؛ فقط حذف صریح محتوا (با تأیید در UI و قابل واگرد) داده را پاک می‌کند.

## رندر

یک partial بازگشتی (`partials/render_container.html`) برای پیش‌نمایش Draft و صفحهٔ منتشرشده. قاب `.rgroup` فقط برای Groupی که عنوان/توضیح/ظاهر دارد نوشته می‌شود؛ ردیف معمولی همان مارک‌آپ قبلی را دارد. محور عمودی با `--cell-span` ارتفاع حداقلی نسبی می‌دهد.

## UI استودیو

`r4_composer.js` + توسعهٔ `r4_resize.js`: انتخاب خانه/گروه (چیپ روی بوم یا لایه‌ها)، نوار ابزار یکسان (ویرایش · چیدمان ۲/۳ افقی و عمودی · کپی · جابه‌جایی · حذف · انتخاب والد · بستن)، پنل لایه‌ها (هدر ← محتوای صفحه ← فوتر)، بازرس گروه (محتوا، تم، متن/فونت، رنگ، پس‌زمینهٔ ساده/گرادیان/تصویر از کتابخانهٔ رسانه/الگو، فاصله، حاشیه/گوشه/سایه، نمایش در دستگاه‌ها، حالت موبایل)، ویرایش درجای عنوان و توضیح گروه، دستگیره‌های تغییر اندازه برای ردیف/گروه والد و فرزند و ردیف‌های عمودی با درصد.

## ماتریس EXISTS / PARTIAL / MISSING (پس از پیاده‌سازی)

| قابلیت | وضعیت | توضیح |
|---|---|---|
| ردیف ساده + نوار ابزار | EXISTS | `row.add`، نوار ابزار یکسان |
| تقسیم ۲/۳ افقی و ۲/۳ عمودی در هر سطح | EXISTS | بازگشتی تا عمق ۸؛ بدون Preset اجباری |
| Group واقعی با تنظیمات مستقل | EXISTS | عنوان، توضیح، نمایش/پنهان، تراز، فونت/اندازه/رنگ، تم، پس‌زمینه، padding/gap/margin، حاشیه/گوشه/سایه، ارتفاع، موبایل، پنهان‌سازی در دستگاه |
| تغییر اندازهٔ هماهنگ | EXISTS | درصد، همسایه‌ها با هم، حداقل، ذخیره در Draft، Undo/Redo؛ نسبت داخلی فرزندان ثابت |
| عدم از دست رفتن محتوا | EXISTS | تست سرویس + Chromium |
| تمام کامپوننت‌های Registry در کتابخانه | EXISTS | همان دیالوگ افزودن به خانه (همهٔ کلیدهای مجاز صفحه) |
| هدر/فوتر روی بوم و قابل کلیک | EXISTS | کلیک روی بوم یا گرهٔ لایه‌ها، ویرایشگر واقعی سراسری |
| PDP آزاد در چارچوب خرید | PARTIAL | ردیف/گروه دور و زیر `product_main` آزاد؛ خودِ `product_main` به اسلات‌های جدا شکسته نمی‌شود (یک فرم، یک variantSelector) |
| ویرایش متن درجا | PARTIAL | عنوان/توضیح گروه روی بوم؛ متن Section ها از بازرس Section |
| پیش‌نمایش واقعی | EXISTS | همان رندر R4 |
| ریسپانسیو دسکتاپ/تبلت/موبایل | PARTIAL | موبایل: stack/slider/ترتیب معکوس + پنهان‌سازی؛ تبلت از دسکتاپ پیروی می‌کند (فقط پرچم پنهان‌سازی جدا) |
| درگ مستقیم خانه‌ها | MISSING | جابه‌جایی با دکمه (↑↓)، نه کشیدن |

## محدودیت‌های شناخته‌شده

* نسبت‌ها صحیح و در گام ۱/۱۲ هستند (دقت اندازه‌گیری ≈ ۸٫۳٪).
* حداکثر ۶ خانه در هر Group، عمق ۸.
* رنگ پس‌زمینهٔ Group هگز است (توکن پالت فقط برای متن/حاشیه)؛ «تم گروه» رنگ فعلی پالت را می‌نویسد.
* در ردیف عمودی، ارتفاع ردیف‌ها «حداقل نسبی» است و محتوای بلندتر آن را بزرگ می‌کند.
* ویندوز و QA ویندوز بررسی نشد؛ فقط Chromium لینوکس.
