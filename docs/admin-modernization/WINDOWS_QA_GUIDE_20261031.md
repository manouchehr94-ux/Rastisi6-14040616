# راهنمای QA ویندوز — چک‌لیست ماندگار، اتصال دامنه، صنف اجباری (۱۴۰۵/۰۸/۰۹)

> هدف: بتوانید خودتان این قابلیت‌ها را روی نسخهٔ ویندوز آزمایش کنید **بدون** پیامک واقعی، DNS/HTTPS واقعی، یا تغییر Production.
> این راهنما فرض می‌کند کدِ این شاخه پس از **مجوز Push و دریافت (fetch) توسط خودتان** در Worktree ویندوز آمده است. من هیچ تغییری در Worktree/دیتابیس/پورت ۸۰۰۸ ویندوز نداده‌ام.

## ۰. قواعد ایمنی (تکرار)
* پورت `8008` و دیتابیس فعلی QA را برای آزمون‌های «نوشتنی» دامنه استفاده نکنید؛ برای بخش ۳ یک **کپی** بسازید (پایین).
* هیچ‌جا SMS واقعی فعال نشود. ورود با **رمز عبور** انجام می‌شود، نه OTP.
* هیچ رکورد DNS واقعی لازم نیست؛ بخش ۳ با ابزار «DNS/HTTPS جعلی» انجام می‌شود.

## ۱. چک‌لیست راه‌اندازی (بدون هیچ تنظیم اضافه)
آدرس: `http://rasti-mode-demo.rastisi.localhost:8008/admin-portal/`

| فروشگاه | انتظار |
|---|---|
| فروشگاه بدون صنف / ناقص | همان چک‌لیست ۲۱ مرحله‌ای در ۵ گروه، با «ادامه‌ی راه‌اندازی» (`data-mode="full"`) |
| فروشگاه با همهٔ مراحل ضروری + منتشرشده | کارت «✅ راه‌اندازی اولیه فروشگاه تکمیل شد.» + وضعیت انتشار + «کارهای ضروری ۱۰ از ۱۰» + دو دکمه |
| منتشرشده ولی بدون روش پرداخت | **جمع نمی‌شود**؛ «منتشر شده است اما هنوز آماده‌ی فروش نیست» + «درگاه پرداخت» در موارد باقی‌مانده |

بررسی‌ها: «مشاهده همه مراحل» → همان ۲۱ مرحله باز می‌شود؛ Refresh → انتخاب شما (باز/بسته) برای همان فروشگاه حفظ می‌شود؛ «تنظیمات اختیاری و رشد فروشگاه» → گروه «رشد و دیده‌شدن» باز می‌شود؛ پیوند «دامنه اختصاصی» → `/admin-portal/settings/?section=domain` (پنل فروشنده، نه پرتال).
بدون جاوااسکریپت هم: `…/admin-portal/?checklist=all`.

## ۲. رجیستری صنف‌ها (بدون خالی‌ماندن فهرست)
```powershell
python manage.py ensure_industry_registry            # فقط گزارش؛ کد خروج ۱ یعنی آماده نیست
python manage.py ensure_industry_registry --apply    # فقط موارد گم‌شده را می‌سازد؛ ردیف‌های موجود را دست نمی‌زند
python manage.py check --database default            # هشدار rastisi.W010 اگر آماده نباشد
```
روی دیتابیس QA فعلی شما (۱۰۷ الگو، ۱۰۱ فعال) باید «✅ رجیستری صنف‌ها آماده است» بدهد و **هیچ چیز تغییر نکند**. روی یک دیتابیس خالی (کپی تازه با `migrate`) فقط با `--apply` پر می‌شود. فروشنده ۲۵ صنف «آمادهٔ تولید» + «سایر (صنف آزاد)» را می‌بیند؛ بقیهٔ الگوها `review_required` هستند و نمایش داده نمی‌شوند (رفتار قبلی، تغییری نکرده).

## ۳. جریان دامنه با DNS/HTTPS جعلی (روی کپی)
1. یک Worktree/پوشهٔ کپی با دیتابیس کپی‌شده بسازید (دیتابیس اصلی را دست نزنید):
   ```powershell
   git worktree add ..\QA_COPY_20261031 HEAD
   copy db.sqlite3 ..\QA_COPY_20261031\db.sqlite3
   cd ..\QA_COPY_20261031
   ```
2. سرور جعلی (پورت ۸۰۱۰؛ هیچ درخواست DNS/TLS واقعی ارسال نمی‌شود):
   ```powershell
   python tools\domain_qa\fake_infra_server.py runserver 127.0.0.1:8010
   ```
3. در ترمینال دوم، «اینترنت جعلی» را مرحله‌به‌مرحله تغییر دهید:
   ```powershell
   python tools\domain_qa\fake_infra_server.py status
   python tools\domain_qa\fake_infra_server.py set txt on        # رکورد TXT «ظاهر شد»
   python tools\domain_qa\fake_infra_server.py set routing on    # رکورد A به راستی‌سی می‌رسد (۲۰۳.۰.۱۱۳.۱۰ = آدرس مستندات)
   python tools\domain_qa\fake_infra_server.py set tls on        # HTTPS آماده
   python tools\domain_qa\fake_infra_server.py reset
   ```
4. ورود: `http://rastisi.localhost:8010/login/` (رمز عبور) → ورود به پنل فروشگاه → «تنظیمات ← دامنه و آدرس».
5. سناریو:
   | کار | انتظار |
   |---|---|
   | ثبت `shop.example.com` | «در انتظار تأیید مالکیت» + رکورد TXT با دکمهٔ کپی، یک دکمه: «بررسی وضعیت» |
   | ثبت `127.0.0.1` / `shop.localhost` | رد می‌شود با پیام فارسی |
   | «بررسی وضعیت» (TXT خاموش) | هشدار «هنوز پیدا نشد»؛ وضعیت عوض نمی‌شود |
   | `set txt on` و «بررسی وضعیت» | «مالکیت تأیید شد» → «نیازمند اقدام شما» + رکورد A پیشنهادی |
   | `set routing on` و بررسی | «در حال بررسی اتصال» + «فعلاً نیازی به انجام کاری از طرف شما نیست.» |
   | `set tls on` و بررسی | «در انتظار تأیید نهایی» + دکمهٔ «تأیید نهایی و فعال‌سازی» (پرتال مالک) |
   | «تنظیمات پیشرفته» | وضعیت‌ها، TXT و A/CNAME (همه با کپی) |
   | چک‌لیست داشبورد | مرحلهٔ «دامنه اختصاصی» همین وضعیت را با یادداشت زنده نشان می‌دهد |
6. **فعال‌سازی نهایی را نزنید** مگر در محیطی که پیامک Step-Up دارید: این مرحله عمداً کدِ پیامکی می‌خواهد (در ویندوز QA پیامک وصل نیست؛ توقف در «در انتظار تأیید نهایی» همان نتیجهٔ درست است).

## ۴. صنف اجباری هنگام ساخت فروشگاه
* با یک حساب مالک آزمایشی (رمز عبور) وارد `http://rastisi.localhost:8008/app/` شوید → «ساخت فروشگاه» → مراحل ← مرحلهٔ «صنف».
* انتظار: دکمهٔ «فعلاً رد شو» وجود ندارد؛ متن «انتخابِ صنف الزامی است … «سایر (صنف آزاد)» را انتخاب کنید».
* ارسال دستی `action=skip` رد می‌شود؛ رفتن مستقیم به آدرس «قالب/لوگو/بازبینی» بدون صنف به مرحلهٔ صنف برمی‌گردد؛ «انتشار» بدون صنف پذیرفته نمی‌شود.
* فروشگاه‌های قبلاً منتشرشده تغییر نمی‌کنند (بدون Backfill).
