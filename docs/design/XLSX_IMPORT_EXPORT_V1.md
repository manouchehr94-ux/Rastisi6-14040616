# XLSX import/export v1

Branch `redesign/xlsx-import-export-v1`. Merchant import/export moves from raw CSV to real
Excel workbooks. Permissions, Store scoping, subscription/export limits, retention, audit
logging and the service-layer mutation rules are unchanged.

## Why XLSX

CSV opened by double-click in Excel on Windows shows mojibake (no BOM, UTF-8 read as a
legacy code page) and, depending on the regional list separator, packs every comma-separated
field into column A. A real `.xlsx` (OOXML, UTF-8 XML inside a ZIP) has neither problem:
text is stored as Unicode, every value lives in its own cell, nothing depends on the user's
regional settings and no import wizard is involved.

Library: **openpyxl** (`openpyxl>=3.1,<4`, pure Python, reads *and* writes). XML/ZIP is never
generated by hand. All workbook code lives in `apps/core/services/xlsx_utils.py`.

Sheet properties: RTL view, styled header (technical headers grey), frozen header row,
auto-filter, column widths, wrapped text with computed row heights, zebra rows, thin borders,
landscape/fit-to-width print setup. Prices/quantities are **numeric cells** (`#,##0`);
dates are **real datetime cells** (`yyyy/mm/dd hh:mm`, Asia/Tehran, no time-zone suffix);
phone numbers, SKUs and barcodes are text-formatted so leading zeros survive. Empty
exports keep their headers and show an amber merged row explaining that nothing matched.

`راهنما` sheet: export type, store, generation time, row count, a short explanation, per-file
notes (e.g. inventory "reserved/sellable are whole-store figures") and a column glossary.
No secrets or implementation details.

Downloads: MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
filename `<type>-<id>.xlsx`. Pre-existing `.csv` ExportJobs (≤7-day retention) still
download as `text/csv`.

### Formula-injection policy (output)

User-controlled text is written through `xlsx_utils.set_text`: the cell is typed as a literal
string and, when it starts with `= + - @` / control characters, Excel's *quote prefix* flag is
set. The value is preserved exactly (no apostrophe prepended) and can never be a formula, even
if the merchant edits the cell afterwards. No formulas are generated anywhere.

## Imports

Primary format `.xlsx`; **CSV remains accepted** for backward compatibility (internal column
names, unchanged behaviour). `.xlsm .xlsb .xls .xltm .ods` are rejected; so is any ZIP
containing `vbaProject.bin`, a macro-enabled content type, >200 entries or >200 MB of
uncompressed data. Limits unchanged: 10 MB file, 20 000 rows, 2 000 chars/field.

The service layer is untouched: `import_xlsx.parse_xlsx_import` is a **mapping layer** that
turns a Persian-header workbook into the exact `{internal_key: value}` rows the existing
validators already consume (`read_job_rows` is the single entry point for preview *and*
execution). Headers are matched ignoring `*`, parentheses, ZWNJ and Arabic/Persian letter
variants; the old internal names and aliases keep working. Values are mapped per Store:
brand/tax class/warehouse **name → code**, category **full path → slug** (a unique leaf name is
also accepted), status label → code, operation label → `set_on_hand`/`adjustment`. Ambiguous
names are reported ("مبهم"), never guessed. Other stores' records cannot be resolved.

Behaviour notes:

* Excel row numbers are preserved (`ImportRowResult.row_number` = sheet row; blank rows skipped).
* Blank cell = "leave unchanged". Tax class is cleared only by the explicit list entry
  «— بدون دسته مالیاتی —».
* Inventory `نوع عملیات` must be chosen explicitly in XLSX (blank is an error); CSV keeps its
  old default. «تنظیم موجودی نهایی» = set exact; «افزایش/کاهش موجودی» = add (negative subtracts).
  Reservation safety is enforced by `adjust_warehouse_stock`, unchanged.
* Numeric columns accept Persian digits and `, ٬ ،` thousands separators.
* **Formula (or error) cells are rejected row-wise** with a Persian message — neither the formula
  text nor a computed value becomes business data. Quote-prefixed/text cells beginning with `=`
  are ordinary text.
* Unknown columns are ignored with a warning on the first row.

### Template workbook (`دانلود قالب`, Store-specific)

`داده‌ها` — header only; required headers are brown with a `*`, optional green; header comments
hold the help text; text-formatted SKU/barcode columns; list dropdowns (data validation pointing
at `فهرست‌ها`) and numeric validations on rows 2–1001.
`راهنما` — numbered instructions + table: ستون · الزامی؟ · توضیح · مقدارهایِ مجاز · مثال · اگر خالی بماند.
`فهرست‌ها` — this Store's brands, full category paths, tax classes (+clear option), warehouses,
statuses, yes/no, inventory operations, active variant-option names.

### Preview, errors, reports

The preview lists total / will-create / will-update / rows-with-errors / rows-with-warnings
(`normalized_data_summary.action` is set by the shared dry-run path). Errors show the Excel
row, the merchant column name and a Persian sentence; stored messages stay untouched and are
re-worded at display time (`describe_errors`). The XLSX error report (`خطاها`) is produced at
preview *and* after execution and contains status, errors, warnings, the original row values,
with failing cells highlighted. The source file downloads in its original format and MIME type.

## Known limits

* Exports are built in memory (openpyxl normal mode): 20 000 rows × 15 columns ≈ 2 s build +
  3 s save, ~130 MB peak. Exports are synchronous like before.
* Dates are Gregorian Excel dates (display format `yyyy/mm/dd hh:mm`), not Jalali.
* Dropdown lists come from the Store at download time; refresh the template after adding brands,
  categories, tax classes or warehouses.
