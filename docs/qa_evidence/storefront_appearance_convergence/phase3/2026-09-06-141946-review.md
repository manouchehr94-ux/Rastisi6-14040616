# Brand end-to-end gate — cart HTMX universal context + Brand CSS convergence

Task 3 adapts the real Cart HTMX fragment (`_render_cart_container`) to go through the same `build_universal_storefront_context` the full `cart_detail` page uses, so a placed pilot section keeps container projection and appearance version after an HTMX action; it moves the Brand tile/logo CSS into the shared `storefront_builder.css` so a `brand_carousel` renders on the four non-Home envelopes that don't load `home.css`; and it adds a large behavioral test suite plus a `--phase3` browser certification matrix. The cart adapter is correct and well-tested, and the harness/browser additions are cleanly gated. The one real problem is in the CSS: the "mirror" rules were appended to a stylesheet that loads *after* `home.css`, so they silently override Home's own Brand-tile styling rather than leaving Home untouched.

Watch for:
- **Home Brand tiles change (confirmed).** The new `.brand-tile`/`.brand-tile img` rules in `storefront_builder.css` load after `home.css` and win the cascade on Home, flipping logo cap 48px→40px, radius 6px→12px, background `#fff`→`var(--card)`, and dropping `min-height:72px`. The spec requires Home unchanged. The browser evidence records the post-change `40px` on Home and the test asserts `40px`, so both codify the regression instead of catching it.

**Verdict**: NEEDS_CHANGES

## High-level view

The cart adapter is the core of the change and it is right: `_render_cart_container` now builds `context = _cart_context(...)` then `context.update(build_universal_storefront_context(request, store, CART, page_context=context))`, the same shape and `.update()` order as `cart_detail` (universal wins). This adds `render_containers`/`use_container_layout` and primes `request.storefront_appearance_version`, which `render_rows.html` needs to branch into container layout — keys the old hand-rolled path never produced. `_cart_context`, pricing, stock reads, and the quantity-clamp/out-of-stock mutation logic are untouched; the template stays `cart_sections_body.html`, so the POST-gated OOB cart-count include is preserved. Store resolution stays on `resolve_store_for_storefront` (fail-closed), matching the other five views.

The CSS fix moves five `.brand-*` rules into the shared stylesheet so non-Home envelopes get tile/logo sizing. The selectors are correctly Brand-scoped with no global spill and `home.css` is not deleted. But the rules are copied from `home.css`'s *first* Brand block (lines 246–250) while Home's effective styling comes from a *second, later* "dense" block (lines 336–340); because `storefront_builder.css` loads after `home.css`, the appended rules now override that dense block on Home. Home is measurably changed, contradicting the spec and the change's own comment.

The V02 anchor truth, draft/published isolation, stable_id-across-clone, six-page presence/asset-envelope, wrapper projection, and registry-membership behaviors are all covered by additive tests (no existing assertions weakened) and all pass. The `--phase3` browser matrix is gated behind `manifest.phase3`/`phase3_fixture`, reuses the single Task-1 harness (no second harness), leaves the default R3 run untouched, and produces real assertion records: 15 envelopes (5 pages × 3 viewports), 45 variant checks, 45 V02 anchor records, cart HTMX badge transitions, wrapper projection stability, and a matched DB restore hash.

### Cart HTMX fragment now carries the universal container/appearance context (V05/A04)

`_render_cart_container` previously called `build_page_render_items`/`build_default_render_items` + `group_items_into_rows` directly and rendered only `render_items`/`rows`. That path never produced `render_containers` or `use_container_layout`, and `render_rows.html` branches on exactly those keys:

```
{% if use_container_layout %}
  {% include "…/render_containers.html" %}
{% else %}
  … flat rows …
{% endif %}
```

So a merchant who placed a pilot section inside a container on the cart page lost the container projection the moment an HTMX update/remove fired — the fragment fell back to flat rows and dropped the appearance version. The adapter delegates to `build_universal_storefront_context`, the same call `cart_detail` makes, with the same `.update()` ordering (universal wins on key collision). `page_context` threads the cart dict so cart-aware sections see the same `cart`/`totals`/`item_count` without re-querying.

The cart's business logic stays isolated from this presentation change: `_cart_context`, `cart_totals`, the stock re-read + `min(quantity, available_stock)` clamp, and the out-of-stock delete path are all outside the diff; the template is unchanged so the POST-gated OOB `header_counts_oob.html` include still fires only on mutations; store resolution stays `resolve_store_for_storefront` (fail-closed: unknown host → 404, non-public store → 403). The six tests in `CartHtmxFragmentCarriesUniversalContextTests` prove the universal keys are present (absent before), Brand placement/order/settings survive, the tile + `?brand=<slug>` link render in the fragment body, the OOB `#cart-count` is preserved, and totals track the legitimately-changed quantity — a clean RED-first characterization of the real bug.

### Brand CSS moved to the shared sheet, but it overrides Home (A06/V06)

The intent is sound: the four non-Home envelopes load `storefront_builder.css` but not `home.css`, so a `brand_carousel` on them had no tile/logo sizing. The five appended rules are all `.brand-*`-scoped (a test walks the delimited block and asserts every selector contains `brand-`), and `home.css` is not deleted.

The defect is cascade order. `home.css` contains two Brand blocks of identical specificity:

```
home.css:246  .brand-tile{…border-radius:12px;background:var(--card)}      (first block)
home.css:247  .brand-tile img{max-height:40px;…}
home.css:338  .brand-tile{min-height:72px;padding:10px;border-radius:6px;background:#fff}   (dense block)
home.css:339  .brand-tile img{max-height:48px}
```

On Home both load and the *dense* block (338–340) wins by source order — Home's real Brand tiles are 48px logos, 6px radius, `#fff`, `min-height:72px`. The diff copied the *first* block (246–250) into `storefront_builder.css:4482`. Because the public envelope loads `home.css` then `storefront_builder.css` (confirmed in the evidence `styleHrefs`: `home.css` index 4, `storefront_builder.css` index 5), the appended rules come last in the cascade and override the dense block on Home:

- `.brand-tile img` cap 48px → 40px
- `.brand-tile` radius 6px → 12px, background `#fff` → `var(--card)`, `min-height:72px` dropped

The browser matrix confirms the changed state: `bounded_img_sample.computedMaxHeight` is `40px` on the **home** envelope, where the pre-change value was 48px (base `storefront_builder.css` had zero `.brand-tile` rules — verified via `git show HEAD`). The spec constraint is "Home unchanged / home.css must not be deleted"; the change satisfies the literal "not deleted" but violates "Home unchanged." A fix must prevent the shared-sheet rules from winning on Home — either scope them to the non-Home envelope roots, or copy the dense values that actually govern Home so the override is a no-op — and back it with a Home before/after assertion.

### V02 anchor truth

`BrandCarouselViewAllAnchorTests` drives the real `_brand_carousel_context` and `brand_carousel.html`: grid and carousel with a resolved destination render `class="more"` + "مشاهده همه" and the href points at the resolved URL; `beauty_tabs` resolves a URL in context but the template branch suppresses the anchor; and `none`/missing/invalid-cross-store destination plus `show_view_all=False` all yield `view_all_url=None` and no anchor (never a dead button). The browser `v02_anchor` records mirror this — 45 records, `present:true`+href for grid/carousel, `present:false` for beauty_tabs.

### Draft/Published isolation, stable_id, wrapper projection

`BrandDraftPublishedIsolationTests` makes a draft-only title edit after publish and asserts the public page still shows the published snapshot with source order preserved. `BrandStableIdentityAcrossPublishTests` asserts a placed `brand_carousel` keeps its `stable_id` across the Published→Draft clone while the PK changes, and that two Brand sections keep distinct stable_ids — the correct identity check (stable_id, not PK). `test_wrapper_hidden_mobile_and_image_background_match_full_preview` renders the section through the standalone `responsive_section_wrapper.html` and through the full Builder preview and asserts the same `data-hide-mobile`/`data-bg-mode`/`data-section-id`/inline background URL/brand anchors appear in both, with the browser `wrapper_projection` record confirming href/asset stability across three replacements.

The `--phase3` flag is `store_true` (default off); `_prepare_r4_sandbox` builds the phase3 fixture only under `if phase3:`, and the runner calls `phase3BrandGate` only under `if (manifest.phase3)`, so scenarios 01–13 and the default fixture are unchanged — the same Task-1 harness threaded through `manifest.phase3_fixture`, not a second harness. `metrics.json` carries real assertions, not just screenshot paths: per-envelope tile counts and slug order, decoded logos vs name-fallbacks, computed image cap, asset-envelope counts (`sb_css`/`htmx`/`alpine` each once), V02 anchor presence, cart HTMX badge transitions (۲→۳→۰ with brand tiles stable across the mutation), and wrapper projection stability. `r4-browser-result.json` is 16/16 PASS including `phase3-brand-gate`, and `db-restore-proof.json` shows `match:true` (pre/post SHA-256 identical).
