# راهنمای QA ویندوز — موتور اعلان‌های مدیران (۱۴۰۵/۰۸/۱۱)

> فقط پس از مجوز Push جداگانه و fetch. این مأموریت **Migration جدید** دارد (`apps/notifications/migrations/0004_inbox_engine.py` — پنج جدول جدید، بدون تغییر در جدول‌های موجود). **ابتدا از دیتابیس QA نسخهٔ پشتیبان/کپی بگیرید و Migration را فقط روی همان کپی اجرا کنید؛ اجرا روی Production یا دیتابیس اصلی QA بدون مجوز مالک ممنوع است.**
> هیچ پرچم خارجی روشن نمی‌شود: `RASTISI_NOTIF_WEBPUSH_ENABLED`، `RASTISI_NOTIF_EMAIL_ENABLED`، `RASTISI_NOTIF_MOBILE_ENABLED` پیش‌فرض خاموش‌اند؛ هیچ کلید VAPID در Repository نیست؛ هیچ ایمیل/Push واقعی ارسال نمی‌شود.

## ۰. آماده‌سازی (کپی دیتابیس)
```powershell
copy db.sqlite3 db_notif_qa.sqlite3          # یا از کپی Postgres استفاده کنید
python manage.py migrate notifications        # فقط روی کپی
python manage.py runserver 127.0.0.1:8010
```

## ۱. اعلان آزمایشی امن (بدون سرویس خارجی)
۱) با مدیر فروشگاه وارد پنل شوید. ۲) زنگ بالای صفحه (کنار دکمهٔ شب/روز) دیده می‌شود. ۳) `/admin-portal/inbox/preferences/` → «ارسال اعلان آزمایشی». ۴) **بدون بارگذاری مجدد** صفحه: شمارندهٔ قرمز زنگ زیاد می‌شود و ظرف حداکثر ۳۰ ثانیه (یا با باز کردن زنگ، بلافاصله) یک Toast پایین‌-چپ نشان داده می‌شود. ۵) تب دوم همان کاربر: همان اعلان دوباره Toast نمی‌شود.

## ۲. بررسی صندوق
`/admin-portal/inbox/`: فهرست، فیلتر (بازه، دسته، اهمیت، جست‌وجو، مرتب‌سازی)، «خوانده شد/خوانده‌نشده»، سنجاق، تعویق (۱ ساعت…)، بایگانی، «همه را خوانده کن»، جزئیات، «رفتن به آن». خروج و ورود دوباره (یا دستگاه دیگر): وضعیت خوانده‌شدن ثابت می‌ماند. اعلان فروشگاه دیگر هرگز دیده نمی‌شود؛ نقش‌ها فقط اعلان‌های مرتبط با مجوز خود را می‌بینند (مثلاً «تحلیل‌گر» اعلان «تغییر نقش» را نمی‌بیند).

## ۳. تنظیمات
`/admin-portal/inbox/preferences/`: خاموش‌کردن Toast، بی‌صداکردن کم‌اهمیت‌ها، حداقل اهمیت، دسته‌ها (دستهٔ «امنیت» قفل است و بحرانی‌ها همیشه در صندوق ثبت می‌شوند)، ایمیل/موبایل «به‌زودی» (غیرفعال).

## ۴. اعلان سیستم مرورگر (Web Push) — صادقانه
- **با پرچم خاموش (پیش‌فرض):** صفحهٔ تنظیمات می‌گوید «ارسال اعلان مرورگر روی این سرور فعال نشده»؛ دکمه‌ای نیست؛ Permission درخواست نمی‌شود.
- مرورگرهای بدون پشتیبانی / آدرس بدون HTTPS: پیام مناسب؛ صندوق و Toast مستقل کار می‌کنند.
- **فعال‌سازی واقعی (فقط با مجوز مالک):** `python manage.py generate_vapid_keys` → کلید خصوصی را فقط در متغیر محیطی `RASTISI_VAPID_PRIVATE_KEY` و `RASTISI_VAPID_SUBJECT=mailto:…` بگذارید؛ `RASTISI_NOTIF_WEBPUSH_ENABLED=1`؛ روی **HTTPS**؛ سپس در تنظیمات «فعال‌سازی اعلان در این مرورگر» (مرورگر فقط پس از کلیک شما Permission می‌پرسد). Push بدون محتوا ارسال می‌شود و Service Worker متن را با نشست خودتان می‌خواند. اینکه اعلان **پس از بسته‌شدن مرورگر** برسد فقط با یک آزمون واقعی روی HTTPS و سرویس Push ثابت می‌شود — در این مأموریت انجام نشده و ادعا نمی‌شود.
- localhost: اعلان سیستم فقط در مرورگرهای پشتیبان و Context امن (localhost مجاز) کار می‌کند؛ iOS/مرورگرهای موبایل پشتیبانی محدود دارند.

## ۵. پنل پلتفرم
با کاربر staff+superuser روی هاست پلتفرم: زنگ + `/inbox/` (رویدادهای: فروشگاه جدید، تغییر وضعیت فروشگاه، پیام تماس، هشدار کارهای زمان‌بندی‌شده). مدیر فروشگاه روی این هاست ۴۰۴ می‌گیرد.
